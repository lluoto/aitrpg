# 预制语音

模组开场白的离线合成结果。文件名是文本内容的哈希（`src/voice/speech-plan.ts` 的 `voiceKey`），
不是模组 ID —— 文案改一个字，键就变，旧音频自然失效，不会出现「文案换了还在念老版本」。

音频与 `manifest.json` 都不入库，随时可重新生成：

```
bun scripts/gen-speech.ts
```

## 为什么只烘开场白

判据是**消息有没有经过 LLM**，不是内容看起来固不固定：

| 层 | 内容 | 合成方式 |
|---|---|---|
| 预制 | 模组开场白（`verbatim === true`） | 离线批量，可换真人配音 |
| 实时 | KP 即兴叙述、NPC 台词 | 流式合成，句级切分 |
| 不念 | 骰点、状态变更、系统提示 | 不合成 |

开场白走的是不经 LLM 的直出路径，加载时内容就已确定，提前合成等于把这部分的首包延迟降为零。
KP 的叙述每次都不一样，预制不了。

路由判定在 `src/voice/speech-plan.ts`，是纯函数，不依赖任何引擎。

## 当前实现只是本机可验证的实现

`scripts/gen-speech.ts` 走 Windows SAPI 的 zh-CN 语音（系统自带、离线、无需密钥）。
这是为了让这条链路能被真正听一遍，**不是对生产 TTS 的选型**。

换厂商只需替换该脚本：清单内容与键的口径由 `speech-plan.ts` 决定，与合成器无关。

生成时会核对每条音频：按块解析 WAV 头拿到真实采样率与时长（SAPI 的 `fmt ` 块是 18 字节，
data 从偏移 38 开始，按固定 44 字节算会得到错的数），再检查峰值排除静音。
当前结果 22.05kHz、3.6–4.4 字/秒，与中文叙述的正常语速一致。

## 实时层还没做

要等两件事：一是 `addMessage` 把尾参收成 options 对象、顺路带上 `mood`（在真相源迁移落地之后做），
二是有了真实音频素材才有依据调切分粒度。

NPC 台词里的括号舞台指示（如 `（声音低沉）`）**不能直接送进合成器**，否则会被当台词念出来。
这些指示不该丢弃 —— 它们是比单一 mood 标签更精细的韵律提示。切分函数放在实时层一起做。
