# Development Retrospective

规划阶段曾多次给出错误前提，执行方必须独立读取源码、运行判据并纠正结论。探针
常见失效模式包括：把局部当全局、预设枚举、把注释当事实，以及用字符串搜索回答
结构问题。

R0-R6 探针纪律：

1. R0: 先确认输入、范围和真相源，不从任务措辞推断实现状态。
2. R1: 优先调用现成判据；工具失败时停止对应结论。
3. R2: 探针必须覆盖正确、目标错误和相似合法输入。
4. R3: 解析 import/结构问题时使用语法感知工具，不用裸字符串代替结构结论。
5. R4: 真实变异必须改坏实际实现，再确认对应判据变红。
6. R5: 记录能力边界；“测试全绿”不等于系统整体正确。
7. R6: 短 prompt 保留决策点和判据，删除重复背景，不用篇幅掩盖未知项。

模型增强是可选能力，不构成当前开发失败。回顾只记录已验证的实现、判据和边界，
不以外部能力状态替代工程结论。
