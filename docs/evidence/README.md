# 被源码引用的实跑证据

这里放的是**代码注释点名引用过**的跑局原文。

## 为什么要单独存一份

`play-logs/` 在 `.gitignore` 里 —— 它是本机跑局的产物，一天能攒几十个。
但有四处源码注释拿其中三个文件当证据：

| 引用处 | 引用的日志 |
|---|---|
| `src/__tests__/dialogue-lead.test.ts` | `run-2026-08-18T06-06-34.txt` |
| `src/play/npc-text.ts` | `run-2026-08-18T06-06-34.txt` |
| `src/__tests__/speech-plan.test.ts` | `run-2026-08-18T03-41-30.txt` |
| `src/llm/generate-llm-expanded.ts` | `run-2026-08-18T06-50-07.txt` |

那些注释写的是「实跑原文见 …」—— 可**克隆下来的人根本打不开那个文件**。
一句指向不存在之物的证据，读起来像有据可查，实际等于没有。

这和这个仓库反复修过的是同一类问题：
摄取入口曾躺在 gitignored 的 `tools/` 里、tsconfig 曾编译 `tools/`、
测试曾读机器本地的 `data/npc.db` —— **仓库状态与本机状态分叉**。

所以：被引用的那几份复制进来入库（共 134 KB），其余 82 个日志仍旧不入库。
判据很简单 —— **代码里引用了哪一份，哪一份就得进得来**。

## 加新证据的规矩

先问自己：这句注释是不是真的需要一份原文才能成立？
需要，就把那一份拷进来；不需要，就别在注释里点文件名。
不要整目录往里倒 —— 这里是证据，不是日志归档。
